# 미팅 링고 패드 (Meeting Lingo Pad) 기획서

작성일: 2026-08-06 · 상태: **v1 웹 앱(`web/index.html`) 완성** — 실시간 번역 API 연동. v0 아티팩트는 참고용으로 유지

## 1. 배경 / 문제 정의

- 해외 화상미팅은 주로 영어로 진행되는데, 비원어민이라 회의 중 단어가 떠오르지 않거나
  표현 방법을 모르는 순간이 생긴다. 회의 중에는 사전을 찾을 여유가 없다.
- 기존 도구(Smooth 등)는 실시간 번역·회의 기록은 지원하지만, **말하는 순간의 단어/표현 제시**는
  지원하지 않는다.
- 목표: 회의 중 **한 페이지에서 조용히 참고**할 수 있는 언어 보조 패드.

## 2. 핵심 기능 (요구사항)

| 4 | AI 분석 어휘 제안 탭 | ✅ 기본: 빈도 기반 추출 + 자동 번역 / API 키 입력 시: **Claude(claude-opus-5) 문맥 분석**(그룹·뜻·예문) |

라이브 안정성: 앱 내 탭 이동은 녹취에 영향 없음(듣는 중엔 라이브 탭에 🔴 표시).
브라우저 탭 백그라운드 전환 대비 onend 자동 재시작 + visibilitychange 재시작 안전장치.
단, 브라우저 창을 닫거나 OS 절전 시에는 중단됨.

### AI 하네스 (모든 Claude 호출에 시스템 프롬프트로 적용 — 도착어별 동적 생성)

1. **도착어에 맞는 스타일 규칙** — 영어는 설정에서 **영국식(기본)/미국식** 선택(철자·어휘·관용구,
   음성 인식 언어도 연동). 일본어·중국어·스페인어·독일어·프랑스어 등은 해당 언어권 비즈니스 문화에
   맞는 격식·경어·관용 표현 사용
2. **직역 금지** — 문맥에 맞는 자연스러운 비즈니스 표현으로. 한국식 겸양 표현은 해당 언어권에서
   자연스러운 표현으로 치환
3. 톤: **professional하되 warm**
4. 사용자 대상 설명·뉘앙스 노트는 한국어로 작성

## 3. v1 아키텍처 (웹)

- **정적 단일 HTML** (`web/index.html`) — 빌드·서버 불필요, 더블클릭(file://)으로도 동작
- **번역 엔진**: Google 번역 비공식 gtx 엔드포인트 (`translate.googleapis.com/translate_a/single?client=gtx`)
  - 무료·키 불필요·CORS 허용. 비공식이므로 향후 차단 가능성 있음 → 차단 시 공식 API 프록시로 교체
- **AI 어휘 분석(선택)**: 사용자의 Anthropic API 키(설정 ⚙, localStorage 저장)로 브라우저에서 직접 호출
  - `POST /v1/messages`, 모델 `claude-opus-5`, `anthropic-dangerous-direct-browser-access` 헤더,
    `output_config.format`(json_schema)으로 구조화 응답 수신
- **오프라인 즉답 레이어**: 내장 한↔영 비즈니스 사전(약 320 항목) — 사전 히트 시 API 호출 없이 즉시 표시

### UI 구성 (한 페이지, 회의 중 산만하지 않게)

1. **상단 고정 헤더** — 검색바(감지 언어 칩·즉시 번역·사전·외부 번역기 링크) + **탭 바까지 함께 sticky**
2. 탭: `회의(라이브+아젠다 2단)` / `전체 번역` / `어휘 제안` / `리포트` / `기록` / `긴급 표현`
3. **회의 탭 2단 레이아웃** — 좌: 라이브(녹취·답변 제안·작문), 우: 아젠다 원문(마크다운+툴팁).
   900px 이하에서는 자동 세로 배치. 전체 폭 1240px로 확대
4. 라이트/다크 테마(OS 설정 따름), 클릭-복사 인터랙션

## 5. 향후 로드맵 — Smooth 벤치마크 기반

Smooth(Frictionless AI)의 기능 축: ① 회의 중 실시간 녹취·번역·요약 ② 문맥 기반 답변 추천 ③ 회의 후
회의록·문장 교정·학습 표현. 이 중 웹에서 가능한 것은 v1.5에 구현 완료(위 표 6~9). 아래는 **현재 웹(정적
페이지) 구조로는 불가능하거나 서버가 필요한 항목** — 추후 구현 대상.

| 항목 | Smooth 방식 | 우리가 필요한 것 |
|------|-------------|------------------|
| 상대방 음성 캡처 | 데스크톱 앱이 시스템 오디오를 별도 채널로 수집 | Electron/Tauri 데스크톱 앱 (웹은 마이크만 접근 가능 — 현재는 스피커 재생으로 우회) |
| 나/상대 화자 분리 | 마이크·시스템 오디오 채널 분리로 해결 | 데스크톱 앱 전제. 웹에선 화자 분리 모델 필요 |
| 고정밀 스트리밍 STT | 외부 STT 전문업체(비공개) | Deepgram/Whisper 등 유료 STT + 키 은닉용 서버(WebSocket 스트리밍). 현재는 브라우저 Web Speech API(무료, 크롬 의존, 억양 민감) |
| 답변 제안 자동 타이밍 | 실시간 문맥 처리 계층(문장 종료 판단·질문 판별·롤링 요약·개입 타이밍) | 경량 LLM 라우팅 + 롤링 요약 파이프라인. 현재는 정규식 질문 감지 + 수동 버튼 |
| 화면 위 오버레이 UI | 항상 위에 뜨는 데스크톱 오버레이 + 단축키 | 데스크톱 앱 (웹은 PiP(Document Picture-in-Picture)로 부분 대체 가능) |
| 계정·캘린더 연동 | Google OAuth + Calendar readonly | 백엔드(서버리스) + OAuth. 회의 일정에서 아젠다 자동 로드 |
| 클라우드 저장·개인화 | GCP 저장, 반복 실수 추적 → 개인화 학습 리포트 | DB(예: Firestore/Postgres) + 회의 누적 분석. 현재는 localStorage 단일 기기 |
| 모델 라우팅 | 번역=경량 모델, 답변 생성=고성능 모델(추정) | 서버 프록시에서 Haiku(번역·감지)/Opus(제안·리포트) 분리 → 비용·지연 최적화 |
| 오디오 비저장 정책 | 메모리 스트리밍 처리 후 즉시 폐기 | ✅ 이미 동일 (Web Speech API 특성상 오디오 미저장, 텍스트만 보관) |
| 결제·구독 | Polar/Stripe | 서비스화 시점에 결정 |

기타: gtx 차단 대비 공식 번역 API 프록시, AI 키 은닉용 서버리스 함수, 발음 듣기(SpeechSynthesis),
표현 즐겨찾기, PWA, 단축키(⌘K).

## 6. 성공 기준

- 회의 중 3초 내에 원하는 단어/표현에 도달
- 화면 전환 없이(탭 1회 이내) 참고 가능
- 아젠다 기반 사전 준비(번역본+어휘)를 회의 전 5분 내 완료
